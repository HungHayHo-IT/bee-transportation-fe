## 4g. Vercel rewrite drops large uploads — the API needs its own HTTPS host

**Open.** Uploads over roughly 3 MB fail intermittently through
`https://bee-transportation-fe.vercel.app/api/*`, while the same request straight to
`http://167.254.68.111/api/*` succeeds every time. Measured 24/08/2026 with multipart POSTs of
random bytes to `/orders/1/files` (unauthenticated, so a healthy hop answers `401` and a broken
one cannot be confused with a business error):

| Size | Through Vercel | Direct to the backend |
|---|---|---|
| 1 MB | 401 · 401 · 401 | 401 |
| 3 MB | 502 · 502 · 401 | 401 · 401 · 401 |
| 5 MB | 401 · 502 · 502 | 401 · 401 · 401 |
| 10 MB | 502 | 401 |
| 20 MB | 502 | — |

The 502 carries `X-Vercel-Error: ROUTER_EXTERNAL_TARGET_CONNECTION_ERROR_CD8` — Vercel's router
failing on the connection to the external target, not a body-size rule, which is why the
threshold is ragged rather than a clean cliff. The backend is blameless: it takes 10 MB
directly without a single failure.

This breaks F1 attachments and F5 file uploads on production for anything but small files, and
the app's own limit is 20 MB per file. It cannot be fixed on the front-end: the browser refuses
a plain-HTTP request from an HTTPS page, and a cross-site `SameSite=Lax` cookie would not travel
even if it allowed it — which is exactly why the rewrite exists.

**The fix is a real HTTPS hostname for the API**, which `DEPLOY.md` §4 already describes (Caddy
issues the certificate automatically). Once it exists, either point the rewrite at it, or drop
the proxy and let the browser call the API directly with `SameSite=None; Secure` on the session
cookie and the front-end origin in `FRONTEND_ORIGIN`. The second removes the proxy hop from the
upload path entirely and is the sounder answer for 20 MB files.

## 4d. Live API drift from `api-docs.md`

Checked 23/08/2026 against `/api/docs-json` (79 paths, local and deployed builds identical).
**The live spec wins.**

| What `api-docs.md` says | What the API actually does |
|---|---|
| `POST /auth/login` returns `{ user, mustChangePassword }` | Returns the session user object directly as `data`; the flag is a field on it |
| `GET /orders/:id/departments` exists | It does not. Quotes and uptake arrive inside `GET /orders/:id` as `departments[]`, already sealed-filtered. Only `POST` on that path exists, for adding a department manually |
| `close` takes `{ departmentId, note }` | `CloseOrderDto` is `{ note? }` — the winner is fixed by `select-quote` |
| Money serialised as a string | Comes back as a JSON number of whole dong |
| JWT payload carries roles and department | Payload is `{ sub, iat, exp }` only; identity is loaded per request, so role changes take effect immediately |
| — | New since the design: `GET /orders/:id/files`, `GET /dashboard/competition/avg-departments`, `GET /reference/{provinces,order-statuses,reject-reasons,order-sources}`, `GET /orders/:id/departments/:deptId/quote-history`, `DELETE /orders/:id/files/:fileId` |
| The representative endpoints return a bare array | **Superseded on 15/09/2026 — see the row below.** The deployed backend wrapped fifteen more lists in the envelope |

`FRONTEND_ORIGIN` now accepts a comma-separated list, so a direct cross-origin call from the
dev server is no longer rejected out of hand. The proxy stays the default anyway: it is what
keeps the `SameSite=Lax` session cookie working.

## 4c. Mock backend

`VITE_USE_MOCK=true` routes every service call to `src/mocks/`. Rules that keep it honest:

- Mocks return the **view types**, never raw API shapes, so components never change when the
  API arrives. The service function is the only place that branches on `isMockMode`.
- `src/mocks/mockUsers.ts` holds eight demo accounts covering all five roles, a dual-role user
  (manager + sale), a user carrying `canViewCompanyReport` without a leadership role, and one
  still on a temporary password. Password for all of them: `beeops2026`.
- The login screen shows a demo-account picker **only** while the mock is on.
- The real session is an httpOnly cookie the browser cannot read, so the mock keeps its own
  session in `localStorage` under `mockSessionUserId` and `mockPasswordChangedUserIds`. Those
  two keys are the mock standing in for the server and disappear with it — application code
  still never stores anything auth-related.

## 4e. Live-API notes gathered while wiring F7

- Every list endpoint answers with `{ items, total, page, limit }` — see §4d. `GET /users`
  also takes `q`, `role`, `departmentId` and `isActive`, so the users screen filters
  server-side rather than in the browser.
- `GET /activity` adds `orderCode` and `orderId` alongside `createdAt`.

  never retrievable again, so the UI must surface it in a dialog.
- Every `/departments`, `/users`, `/services` write is admin-only; a leader gets `403`.
- Admin account for local testing: the password lives in the backend repo at
  `scripts/qa/qa_lib.py` (`ADMIN_PW`). QA accounts `qa.*@bee.vn` share `BeeOps@2026!x`.

## 4f. Province names belong to the backend

`GET /reference/provinces` is the catalogue and the backend validates against it: a known
alias (`HN`, `hai phong`) is normalised on write, an unlisted name is rejected with a `400`
naming the catalogue. The old free-text mess (`Hà Nội` beside `HN`) was normalised by
migration 001.

`useProvinces()` fetches the list once per session and shares it; `src/constants/provinces.ts`
is now only the offline fallback, so an empty select can never block order creation.
**Still unconfirmed with the user**: the catalogue holds the 34 units in force after the 2025
merger — if the company still works with the old 63, that is a backend change now, not a
front-end one.

## 5. Domain facts worth not re-deriving

- Ten services and their order-code prefixes: `CON` consulting, `CUS` customs, `DOM` domestic,
  `PRJ` project cargo, `LIF` lifting, `MMT` multimodal, `PKG` packing, `CBT` cross-border,
  `BRK` shipbroking, `RNT` equipment rental.
- Order code `[SERVICE]-[YYYYMMDD]-[NNN]`, sequence per service per day, generated by the
  backend.
- Roles: `admin`, `leader`, `manager`, `sale`, `staff` — a user may hold several and
  permissions are the union. Plus the per-user `canViewCompanyReport` flag.
- Revenue is measured by `closedAt`, never `createdAt`.
- Milestone sets are snapshotted at closing time; editing a service template never touches a
  closed order.
- Money crosses the wire as a JSON number of whole dong and is formatted to `vi-VN` with a
  `₫` suffix through `formatCurrencyVnd`. `null` means "you may not see this", never zero.
